## C1 — P2: ordinary ignored files turn a clean repository into an inconclusive review

**Classification:** new operational regression/policy defect; current, reproduced. Not an exploit or an omitted-source false negative.

**Evidence:** [src/mergecraft/utils/offline_diff.py:163](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/src/mergecraft/utils/offline_diff.py#L163), lines 171–180 list all ignored working-tree paths; lines 289–292 enable this on default materialization. [src/mergecraft/offline_review.py:858](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/src/mergecraft/offline_review.py#L858), lines 859–875 convert an empty diff with those paths into `inconclusive`.

**Trigger/proof:** disposable repository with committed `.gitignore` containing `.venv/`, unchanged tracked source, and an existing ignored `.venv/installed` file. `git status --porcelain` is empty. Actual `review --cwd <repo> --base main --dry-run` exits **20**, reporting “every change was excluded from coverage” and naming `.venv/`.

**Impact:** ordinary dependency installations, ignored generated files, artifacts, or `.env` prevent clean empty-diff results. The code treats existence of ignored content as evidence of an excluded change even though Git reports no source changes. This also creates routine incompleteness warnings on nonempty reviews.

**Intent check:** the current tests intentionally expect ignored source names to be reported; this is not an accidental typo. The defect is the broad policy's behavior in an ordinary clean development checkout. Reporting ignored content as informational inventory is distinct from declaring the review incomplete.

**Test gap:** [tests/utils/test_offline_diff_coverage_limits.py:66](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/tests/utils/test_offline_diff_coverage_limits.py#L66) checks a pristine clean fixture without ignored dependencies/build files. [tests/utils/test_offline_diff_untracked.py:200](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/tests/utils/test_offline_diff_untracked.py#L200) explicitly tests ignored paths as limitations but not ordinary clean-environment behavior.

**Fix sketch:** separate ignored/out-of-scope workspace inventory from eligible changed-source exclusions. Preserve incomplete coverage for oversized/unreadable eligible source without treating every ignored artifact as a change. Add a clean checkout containing a normal virtual environment/build directory.

**Effort:** S–M. **Fix risk:** MED (coverage policy semantics). **Confidence:** HIGH in observed behavior and common usability impact.

## C2 — P2: explicit --unstaged discards exclusion metadata and can report passed without examining changed source

**Classification:** new confirmed defect in the current mode-specific path.

**Evidence:** [src/mergecraft/utils/offline_diff.py:246](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/src/mergecraft/utils/offline_diff.py#L246), particularly line 252, discards the limitations returned by `_discover_untracked_additions`. [src/mergecraft/utils/source_resolve.py:557](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/src/mergecraft/utils/source_resolve.py#L557) materializes the returned text without restoring them. The empty/no-limitations success path is [src/mergecraft/offline_review.py:885](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/src/mergecraft/offline_review.py#L885), lines 885–891.

**Trigger/proof:** the repository has one eligible untracked Python file over the 256 KiB limit. Actual `materialize_resolved_diff(... unstaged=True)` returns `empty=True` with no limitations. The actual `_OfflineDiffReviewRun.review` method returns `success=True`, `outcome=passed` for that materialization. No provider is needed because the empty fast path returns before model execution.

**Impact:** oversized, binary, non-UTF-8, and symlink additions can disappear from this mode's result. Default materialization reports these exclusions, but explicit unstaged mode loses the reason. This is narrower than claiming every skipped binary should be reviewed: the issue is a clean result despite a known materialization omission.

**Test gap:** [tests/utils/test_offline_diff.py:55](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/tests/utils/test_offline_diff.py#L55) and line 108 test no-crash behavior for omitted binary/non-UTF-8 input; omission-to-review-outcome coverage is concentrated on the default materialization path.

**Fix sketch:** preserve structured materialization and coverage metadata through all source modes. Apply one consistent incomplete-review outcome policy and add an oversized-only unstaged integration fixture.

**Effort:** S. **Fix risk:** LOW. **Confidence:** HIGH.

## C3 — P2: highest-layer-only validation falsely reports inherited configuration as valid

**Classification:** residual/incomplete-fix variant of the earlier layered-validation issue; current and re-probed, not a wholly new historical bug. The defect is validator false assurance, not the documented runtime fallback itself.

**Evidence:** [src/mergecraft/cli/config_surface_cmd.py:85](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/src/mergecraft/cli/config_surface_cmd.py#L85) selects one path for `config validate`; lines 174–186 do the same for review preflight. [src/mergecraft/config/layered.py:139](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/src/mergecraft/config/layered.py#L139) returns only the highest-precedence contributor. The runtime loader at lines 45–52 logs parse failures and substitutes `{}`, while lines 80–88 merge the remaining layers.

**Why the lower layer matters:** this is a merge contract, not replacement-file precedence. [docs/agent-roster.md:84](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/docs/agent-roster.md#L84) states that local overrides merge over the committed file for CLI runs. The implementation deep-merges dictionaries at `layered.py:33–42`, and [tests/config/test_layered_config.py:22](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/tests/config/test_layered_config.py#L22) tests that behavior. `MERGECRAFT_CONFIG` is a separate sole-file override; this probe does not set it.

**Trigger/proof:** committed configuration first contains `shell: disabled`, and local configuration contains only `models: []`. Actual runtime settings correctly retain `shell=disabled`. Then append malformed, unrelated `runBounds: [` to the committed file. The same local file now causes `config validate` to exit **0**; review preflight accepts it; runtime loads with `shell=restricted`. The inherited policy is lost because the whole committed YAML failed to parse, not because the local overlay intentionally overwrote it.

**Design-policy qualification:** [docs/config-failure-policy.md:42](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/docs/config-failure-policy.md#L42) explicitly documents that syntactically broken committed YAML warns and falls back to defaults; lines 156–158 tell operators to fix broken YAML while restricted defaults apply. The observed runtime fallback follows that policy and is not reported here as an undocumented security vulnerability. In contrast, the explicit `config validate` command rejects malformed YAML when it selects that same file directly (`config_surface_cmd.py:89–92`), but adding a valid overlay hides it from validation.

**Impact:** validation says “ok” although an active inherited file is malformed and runtime falls back instead of applying it. The shell-value control demonstrates that this lower file matters to the effective configuration, not a proven privilege bypass. No shell execution was attempted. Operators cannot rely on the validation result to distinguish their intended shared configuration from defaults.

**Test gap:** [tests/cli/test_config_surface.py:84](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/tests/cli/test_config_surface.py#L84) and lines 100–130 cover invalid single-file configuration, not a malformed contributing lower layer with a valid overlay.

**Fix sketch:** make explicit validation inspect every contributing file with source-specific errors, migrate/merge according to the runtime contract, then validate the effective merged configuration. Preserve or deliberately revisit runtime warn/default behavior separately; do not silently change that documented policy as part of a validator fix. This also does not require rejecting a superseded scalar solely because the lower scalar would be invalid in isolation; the demonstrated YAML syntax error prevents determining the inherited configuration at all.

**Effort:** M. **Fix risk:** MED (migration and override compatibility). **Confidence:** HIGH.

## C4 — P2: behavior-verification repo_path is accepted but ignored for startup and settings

**Classification:** new confirmed implementation gap; behavioral evidence HIGH, documentation-level semantics MED.

**Evidence:** [src/mergecraft/verify/models.py:147](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/src/mergecraft/verify/models.py#L147) requires `repo_path` at line 153. [src/mergecraft/cli/verify_behavior_cmd.py:332](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/src/mergecraft/cli/verify_behavior_cmd.py#L332) loads YAML input but line 346 loads settings from the caller's `Path.cwd()`. [src/mergecraft/verify/runner.py:550](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/src/mergecraft/verify/runner.py#L550) passes only the startup command to `_start_app`; lines 185–193 create the subprocess without a `cwd`.

**Documentation vetting:** [docs/verify-behavior.md:47](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/docs/verify-behavior.md#L47) advertises YAML input, and line 248 lists `repo_path` in the public input contract, attributing it to issues 62/63. However, the current prose does not explicitly say “chdir to repo_path” or promise checkout of `base`. Therefore this is framed as a required public input that has no operational effect, with a predictable wrong-directory consequence—not as a proven violation of an explicit checkout guarantee. Lines 168–183 already qualify what a green verification proves.

**Trigger/proof:** an actual `run_verify_behavior` call receives a valid input naming repository B and `startup_command="python app.py"` while the process is in A. The intercepted subprocess receives `cwd=None`, hence inherits A. The runner returns blocked because the probe deliberately supplies no driver after recording startup. It does not fabricate a successful browser verdict and does not launch an app.

**Impact:** relative startup commands can start a different app or fail when the YAML is invoked from another directory. The CLI also consults A's `shell`/`verify_behavior.enabled` settings instead of B's. The `base` input likewise has no runner use, but this memo does not count that separately or claim a branch comparison was promised.

**Test gap:** [tests/verify/test_artifacts_and_lifecycle.py:178](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/tests/verify/test_artifacts_and_lifecycle.py#L178), lines 184–205, uses an absolute script path and thus does not exercise a distinct target workspace.

**Fix sketch:** decide and document the workspace semantics, resolve the named workspace once, and apply it to settings and relative startup inputs. If the command deliberately only operates on the caller's workspace, reject an inconsistent `repo_path` instead of accepting an ignored value.

**Effort:** S–M. **Fix risk:** MED. **Confidence:** HIGH in mechanics; MED in intended public semantics.

## C5 — P2: local coverage detects a consumer executable but runs a different Python environment

**Classification:** new compatibility defect; conditional, not universal failure.

**Evidence:** [src/mergecraft/ci/local_evidence.py:275](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/src/mergecraft/ci/local_evidence.py#L275), lines 275–280, accepts `coverage` found on `PATH`. Lines 333–344 instead invoke `sys.executable -m coverage run -m pytest`; lines 359–369 use the same interpreter for JSON export. Lines 768–775 convert execution failure to a skipped local-evidence result. [README.md:50](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/README.md#L50) and [docs/install.md:34](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/docs/install.md#L34) recommend isolated `uv tool install`.

**Trigger/proof:** supply a consumer virtual environment's `coverage` via the discovery seam. Availability returns true, but the captured invocation selects mergeCraft's own interpreter, never the discovered executable. The existing isolated CLI interpreter used here has neither `coverage` nor `pytest`. The coverage subprocess is mocked and returns a synthetic failure; no actual consumer test or sandbox is run.

**Compatibility qualification:** this does work when mergeCraft's interpreter also contains coverage, pytest, and the consumer's imports. It fails or tests the wrong environment when an isolated CLI tool environment differs from the consumer test environment. A successful `which coverage` cannot establish availability for the interpreter the code actually selects.

**Impact:** `--with-coverage` may skip despite a correctly provisioned consumer toolchain, or fail imports because only the CLI environment is used. The probe establishes interpreter mismatch, not end-to-end sandbox behavior on every platform.

**Test gap:** add a fixture with distinct CLI and consumer interpreters/executable discovery. Existing artifact injection and mocked execution paths in [tests/cli/test_review_coverage_mutation.py:435](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/tests/cli/test_review_coverage_mutation.py#L435) do not establish that the executed interpreter owns the detected toolchain.

**Fix sketch:** resolve one consumer coverage/test interpreter, validate it, and use it consistently for collection and export under the existing sandbox. Name the selected toolchain and failure in the result.

**Effort:** M. **Fix risk:** MED. **Confidence:** HIGH in mismatch and the isolated-environment trigger.

## CLI versus Action and command depth

The CLI has a substantial review core, multiple source selectors, structured exports, local configuration, and optional execution features. Its weaker boundary is selecting one consistent workspace/configuration/credential/toolchain context across those features. The Action obtains a predetermined checkout and consumes declared CI receipts, avoiding some local-environment ambiguity; this memo does not claim the Action is otherwise free of defects.

Auxiliary commands have narrower implementations than a broad product comparison might assume:

- [src/mergecraft/cli/ask_cmd.py:38](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/src/mergecraft/cli/ask_cmd.py#L38) returns a line excerpt or canned response; help explicitly says the question is not sent to a model at lines 73–86.
- [src/mergecraft/cli/replay_cmd.py:31](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/src/mergecraft/cli/replay_cmd.py#L31) summarizes session identity and event count; it does not rerun a reviewer.
- [src/mergecraft/cli/run_cmd.py:115](https://github.com/alexhawat/mergeCraft/blob/55cf88e33c318a8b03a251fb0f8b6dad9d999141/src/mergecraft/cli/run_cmd.py#L115) compares sets of event kinds, not finding changes or outcome quality.

These are current capability limitations, not falsely advertised hidden bugs: present help discloses the narrow behavior. Competition analysis should compare actual review, triage, conversation, replay, and verification behavior rather than command names alone.
