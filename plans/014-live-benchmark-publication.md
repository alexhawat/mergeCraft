## Intent and verified current state

The repository has structural replay and a one-model-per-invocation live detection harness, but no accepted live quality publication. Replaying stored expected decisions does not measure a provider's ability to find defects. The existing two-case smoke manifest is preparation only and its labels are agent-seeded. A campaign must record failures, label status, and provenance instead of manufacturing comparable scores.

## Ordered steps

### 1. Make the campaign concrete

Keep `smoke-manifest.json` as the frozen readiness artifact: exactly `bench-adversarial-clean-diff` and `bench-correctness-boundary`, with the checked-in hashes and `label_status` still declaring agent-seeded labels. Do not mutate it into evidence of calibration. Freeze a separately independently adjudicated, patch-bearing detection corpus: every `baseline.json` label must map to the exact patch/hash a human reviewed. Golden metadata from 011, trajectory labels from 012, and paired judge decisions from 013 are different artifacts; reuse is allowed only through an explicit evidence mapping and re-adjudication for the detection baseline.

After both that detection corpus and 013's judge-calibration receipt exist, create `campaign-manifest.json` with `schema_version`, `campaign_id`, corpus commit, case IDs and patch/baseline hashes, detection-label receipt hash, judge-calibration receipt hash, exactly two distinct full `provider/model` slugs from distinct providers, per-review timeout/token/cost limits, `retry_limit: 0`, expected case count, and total campaign spend ceiling. This first campaign does not retry: a failed case fails the campaign and a rerun gets a new campaign ID. Provider/model entries and spend ceiling are operator-owned required values with no defaults.

Implement strict manifest/report validation in `publication.py`: reject unknown fields, duplicate models, non-disjoint provider identities, hash drift, agent-seeded/ineligible labels for comparative claims, missing 013 validation, empty corpora, and unset/non-positive limits. Never read or persist credential values.

Verification: Manifest validation proves the same case IDs/hashes and protocol apply to both providers; no live invocation occurs before the operator's choices and budget.

### 2. Reconcile publication scope

Use the existing metric semantics exactly. Recall is `found/total_issues`. On open-world cases, `corpus_confirmed_precision` is a lower bound and unmatched findings remain `unadjudicated`; do not call them false positives. `strict_precision`, `false_positives`, false positives per case, and clean-case FP rate are publishable only for closed-world rows. F1 must be named `corpus-confirmed F1` when it uses the open-world lower-bound precision. Report each provider separately with `cases_run`, `cases_failed`, failed IDs, expected case count, total issues/reported/found, uncertainty intervals, raw artifact path/hash, and model/prompt/judge/rubric/corpus pins. Measure wall-clock latency in the campaign runner. Record provider-reported cost only when available; otherwise emit `cost_known=false`, `cost_usd=null`, and the configured budget ceiling, never zero. Never average providers into one ranking.

Follow the current measured-report plus README-link policy. Replace the old strict-xfail README-number test with a test for a dated report and link only after real results exist. Do not publish a leaderboard or landing-page numeric table unless the operator explicitly reverses `docs/eval-methodology.md` and the docs gate in a separately reviewed decision.

Verification: tests/evals/test_benchmark_publication.py and docs-check pass. Report template includes limitations, sample sizes and errors.

### 3. Run smoke then bounded campaign

Treat any preliminary live smoke invocation as a separately declared campaign with its own case count, reservation, and explicit allocation from the approved total budget. Do not hide additional smoke attempts in a reservation calculated only for the later full corpus; the sum of all campaign reservations must fit the overall ceiling. Agent-seeded smoke results establish execution readiness only.

With the manifest approved and credentials available in the operator environment, materialize a temporary detection corpus containing only manifest cases and revalidate hashes. Before any provider invocation, compute the conservative reservation `2 * expected_case_count * per_review_cost_budget_usd`; refuse to start unless it is at or below the approved total ceiling. This is an authorization bound, not claimed actual spend. Run `bench-detect` once for each exact model with the manifest's per-review bounds (`MERGECRAFT_RUN_TIMEOUT_S`, `MERGECRAFT_TOKEN_BUDGET`, `MERGECRAFT_COST_BUDGET_USD`) and one common campaign results directory. `run_detection` loops the whole corpus inside one invocation, so an external wrapper cannot honestly enforce the total between cases; the up-front reservation is the bound. Preserve result sets and raw findings. A missing `detection`, `cases_run != expected_case_count`, any failed case, pin mismatch, or hash drift fails campaign acceptance; never retry silently or score a failed call as a clean review.

Verification: Both models have an attributable nonempty detection report. Missing detection, zero executed cases, hash drift or exceeded spend aborts expansion.

### 4. Publish auditable results

Add `mergecraft eval publish-benchmark --manifest ... --result ... --result ... --output ...` as a keyless aggregation step and an `eval-publish-benchmark` Make wrapper parameterized by manifest/result/output variables. It must load both files through `BenchmarkResultSet`, verify their detection model/pins/corpus against the manifest, recompute table values from case results, and refuse ineligible/missing/partial inputs. Write a dated report plus machine-readable summary under `evals/results/<campaign-id>/`; include defined metrics, uncertainty, limitations, errors, known-or-unknown cost fields, the conservative reserved ceiling, and exact reproduction commands. Regenerate `docs/cli.md` with `make docs`. State that reruns follow a reproducible protocol but stochastic outputs need not be byte-identical. Add only a README link. Close #140 only after the operator accepts the report and publication contract.

Verification: Publication tests/docs-check pass; every table value can be recomputed from preserved records; structural latest.json remains the structural baseline.
