## Ordered steps

### 1. Correct the claim immediately

Rename human-visible output to `label eligibility: eligible|ineligible`; an all-independent corpus may say eligible but never calibrated. Preserve the existing JSON field name `calibration` and `CalibrationStatus` shape in `ScoreReport` and `DetectionMetrics` for backward compatibility; changing that wire key requires a result-set schema-version migration and explicit old-artifact reader tests. Add a separate optional judge-calibration report rather than overloading `CalibrationStatus`. Update the current tests that literally expect `calibrated`, and add a compatibility test that older result sets still deserialize.

Verification: Focused formatting tests prove provenance eligibility and completed calibration are different states.

### 2. Freeze the evaluation design

Create strict models in `judge_calibration.py`: `JudgeCalibrationCase(case_id, finding: AgentFinding, deterministic_checks, lane, evidence_sha256, human_reference, human_adjudicator_login, human_adjudicated_at, saved_judge_verdict: JudgeVerdict, provenance, adjudication)` and `JudgeCalibrationProtocol(schema_version, calibration_case_ids, held_out_case_ids, case_hashes, minimum_per_class, minimum_macro_f1, minimum_drop_precision, minimum_confirm_recall, minimum_kappa, maximum_disagreement_rate, required_high_stakes_escalation_recall)`. `AdjudicationRecord` identifies the adjudicator kind but not a particular human, so login/timestamp are required separately and must come from the real decision. `human_reference` uses exactly `confirm|downgrade|drop`, with `new_severity` required for downgrade, matching `JudgeVerdict`. For high-stakes judge drops, report the raw `drop` class and separately evaluate that policy produced `escalated_to_human=True`; do not relabel the raw verdict as a fourth class.

The protocol file must provide every numeric threshold explicitly, with no permissive defaults, before any held-out score is read. Reject split overlap, duplicate IDs, hash drift, missing judge/provider/model/judge-version/rubric-version pins, missing deterministic checks, agent-seeded reference truth, and class counts below `minimum_per_class`. Alex's nine metadata rows in 011 do not contain candidate findings or paired judge verdicts and cannot satisfy this dataset.

Verification: Validation rejects overlaps between calibration and held-out sets, missing pins, empty sets, unsupported label mappings and agent-seeded truth.

### 3. Implement the offline report

Compute a 3×3 confusion matrix over raw `confirm|downgrade|drop`, per-class precision/recall/F1, micro/macro values, disagreement rate, and Cohen's kappa for paired judge/human decisions. Zero-denominator values serialize as `null`. Kappa is undefined only when the paired set is empty or `1 - p_e == 0`; a one-class human reference with varying judge predictions can validly yield kappa `0`, though the report must flag its class-coverage limitation and the protocol's minimum-per-class gate may still reject it. Report downgrade severity agreement separately. Report high-stakes escalation recall from policy outcomes separately from raw-class metrics. Judge-human kappa is paired model/human agreement; human-human reliability is a distinct study requiring a second human. Preserve the single-human limitation and sample counts. `mergecraft eval judge-calibration --protocol PATH --cases PATH --json` must operate entirely on saved verdicts with no provider credential.

Verification: Known paired-rating fixtures match hand-computed counts/kappa; undefined statistics remain explicit, never coerced to perfect agreement.

For each class, compute F1 directly as `2*TP / (2*TP + FP + FN)`: an entirely missed class with positive FN has F1 zero even if precision is undefined. For kappa, use `p_o = diagonal_sum/n` and `p_e = sum(row_total[c]*column_total[c])/n**2`, then `(p_o-p_e)/(1-p_e)`. Include fixtures for missed classes, one-class reference with varying predictions, and identical single-class ratings.

### 4. Evaluate and enforce only valid candidates

Fit/select a candidate only on the frozen calibration split. Seal the candidate identifier, policy parameters, protocol hash, dataset hashes, and acceptance contract before running the held-out split once. The held-out report passes only if every explicit threshold is met; undefined required metrics fail closed. Failed candidates remain provisional and a changed candidate requires a new held-out version, not repeated tuning on the same holdout. Keep structural eval CI separate and keyless. Record states as `eligibility_only`, `provisional`, `validated`, or `rejected`.

Verification: make eval-judge-calibration accepts a passing frozen candidate and rejects an intentionally failing one; missing human data cannot pass a calibrated threshold gate.
